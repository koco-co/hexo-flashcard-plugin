# 功能域：云端同步

- 文档状态：已确认
- 功能域 ID：cloud-sync
- 依赖功能域：local-progress

## 功能域范围

本域覆盖可选 GitHub 登录、Supabase 跨设备同步、离线上传队列、卡片与新卡首次开始记录合并、每日新卡额度的跨设备约束、退出登录和全局重置。未配置同步或未登录时，插件保持完整的本地学习闭环；本域不提供邮箱密码、多登录提供商、社交关系、共享卡组或实时协作。

## 用户能力与旅程

读者未登录时，每次评价立即写入当前浏览器，并可选择“使用 GitHub 登录并同步”。登录完成后，插件在后台把本地 v3 快照提交给数据库事务；数据库按稳定卡片 ID 合并状态、按日期合并每日任务和新卡首次开始记录，并对每个自然日的新卡首次开始数执行 50 张上限，最后返回完整快照。另一设备使用同一 GitHub 账号登录后获得合并结果。离线或云端失败只改变同步状态提示，本地复习不被阻塞。退出登录保留当前浏览器数据；登录状态下的重置必须输入 `重置`，云端事务成功后才清空本地。

## 功能详细设计

### F-017 可选 GitHub 登录与本地优先写入

#### 作用与目标

让静态博客在不牺牲匿名本地模式的前提下提供跨设备身份。

#### 适用角色、入口与前置条件

宿主已启用 Supabase 同步配置；读者进入 `/learn-topic/`。

#### 用户输入契约

| 输入项 | 提供者 | 必填 | 格式与范围 | 示例 |
| --- | --- | --- | --- | --- |
| GitHub 登录 | 读者 | 否 | OAuth 授权 | 点击登录按钮 |
| 复习评价 | 读者 | 是 | 忘记、模糊、记得、简单 | 记得 |
| Supabase 配置 | 宿主 | 是 | URL 与 publishable key | 通过环境变量注入 |

#### 可见界面状态与交互

状态 1：未登录本地模式

```text
复习进度
未登录，进度仅保存在此浏览器
[使用 GitHub 登录并同步]
```

进入条件：同步已配置但读者未登录。评价卡片会立即保存到本地并继续复习；点击登录后进入 GitHub 授权状态。

状态 2：GitHub 授权

```text
复习进度
正在前往 GitHub 登录…
```

进入条件：读者点击登录。授权成功后回到原复习页并进入同步状态；取消或失败后回到本地模式，本地进度不变。

状态 3：同步完成

```text
复习进度
本地与云端进度已同步
[立即同步] [退出登录]
```

进入条件：已登录且云端返回合并快照。继续评价时先保存本地再后台同步；退出登录后回到本地模式。

#### 产品状态流

```text
进入复习页 → 未登录则使用本地模式 → 可选 GitHub 授权 → 返回原复习页 → 异步合并 → 同步完成
评价卡片 → 立即保存本地 → 已登录则后台同步，未登录则结束
```

#### 输出契约

| 输出内容 | 呈现形式 | 触发条件 | 语义要求 | 完整示例 |
| --- | --- | --- | --- | --- |
| 本地模式 | 同步状态栏 | 未登录 | 全部学习功能可用，不请求用户进度 API | `未登录，进度仅保存在此浏览器` |
| 登录入口 | 按钮 | 未登录且配置有效 | 只提供 GitHub | `使用 GitHub 登录并同步` |
| 本地保存 | localStorage v3 | 每次评价 | 必须先于云端请求完成 | 刷新后立即恢复 |

#### 设计依据

用户确认匿名读者保持完整本地能力，登录提供商只使用 GitHub；Supabase 官方 GitHub Auth 流程提供 OAuth 登录和回调契约。

#### 行为样例

- `SAMPLE-SYNC-001`：未登录评价后立即保存本地。
- `SAMPLE-SYNC-002`：GitHub 登录后合并登录前进度。

#### 验收标准

- `F-017-AC-01` Given 读者未登录，When 完成一次评价，Then 进度立即写入 localStorage 且复习继续，不等待任何网络请求。
- `F-017-AC-02` Given 宿主启用同步，When 读者点击登录，Then 只发起 GitHub OAuth，回到原复习页后开始后台同步。
- `F-017-AC-03` Given 宿主未启用同步，When 读者学习和刷新，Then 本地闭环保持可用且页面不加载 Supabase 资源。

### F-018 原子合并与离线恢复

#### 作用与目标

在多设备并发、离线和失败场景下保留每张卡最新状态及完整每日历史。

#### 适用角色、入口与前置条件

读者已通过 GitHub 登录；至少一个设备具有本地进度，或云端已经存在同一账号的进度。

#### 用户输入契约

| 输入项 | 提供者 | 必填 | 格式与范围 | 示例 |
| --- | --- | --- | --- | --- |
| 本地快照 | 浏览器 | 是 | v3 cards、days 与 newCardDays | 当前 localStorage |
| 重置版本 | 浏览器 | 是 | 非负整数 | 0 |
| 登录身份 | Supabase Auth | 是 | `auth.uid()` | 当前 GitHub 用户 |

#### 可见界面状态与交互

状态 1：正在同步

```text
复习进度
正在同步，本地操作不受影响
[立即同步] [退出登录]
```

进入条件：已登录且开始上传或读取。读者仍可继续评价；成功后显示同步完成，断网或失败时进入对应恢复状态。

状态 2：离线待同步

```text
复习进度
当前离线，本地进度将在联网后同步
[立即同步] [退出登录]
```

进入条件：浏览器离线。评价继续写入本地；恢复联网后自动重试并进入正在同步。

状态 3：云端失败

```text
复习进度
云端暂不可用，本地进度已安全保存
[立即同步] [退出登录]
```

进入条件：登录、同步或重置请求失败。读者可继续本地复习，也可点击立即同步或等待联网后自动重试。

#### 产品状态流

```text
本地快照提交 → 云端按卡片、每日任务和新卡开始记录合并 → 应用每日新卡上限 → 返回完整快照 → 更新本地 → 同步完成
请求失败或离线 → 保留本地与待上传状态 → 继续复习 → 恢复联网或手动重试 → 再次合并
```

#### 输出契约

| 输出内容 | 呈现形式 | 触发条件 | 语义要求 | 完整示例 |
| --- | --- | --- | --- | --- |
| 卡片合并 | 本地与云端快照 | 同一 ID 冲突 | 较大的 `last_review` 胜出；相等时不覆盖现有云端记录 | 手机 10:30 胜过电脑 10:00 |
| 每日历史合并 | 月历 | 日期与卡片重复或只存在一端 | 任务取并集；完成时间保留非空且较新的值 | 两台设备的日期都保留 |
| 新卡开始合并 | 新卡队列 | 同一账号、同一日期、多设备开始新卡 | 首次开始卡片 ID 去重；服务端每个 Asia/Shanghai 日期最多保留 50 张，返回结果作为跨设备额度基准 | 两台设备合计最多 50 张 |
| 离线队列 | 同步元数据 | 网络失败或离线 | 本地不回滚，联网后自动重试 | `当前离线，本地进度将在联网后同步` |

#### 设计依据

用户确认按稳定卡片 ID 使用较大的 `last_review`，并合并每日完成历史；Supabase RLS 官方指南用于约束每位登录读者只能访问自己的记录。

#### 行为样例

- `SAMPLE-SYNC-003`：两端同一卡片由较新评价胜出。
- `SAMPLE-SYNC-004`：离线评价保留本地并在联网后重试。
- `SAMPLE-SYNC-007`：两台设备合计开始 50 张新卡后，另一台设备只能继续已开始卡，不能新增第 51 张未开始卡。

#### 验收标准

- `F-018-AC-01` Given 两台设备修改同一卡片，When 任一设备同步，Then 数据库事务保存 `last_review` 较大的状态并返回合并快照。
- `F-018-AC-02` Given 两台设备具有不同日期任务，When 同步，Then 每日任务与完成历史取并集，不删除只存在一端的记录。
- `F-018-AC-03` Given 读者离线或云端请求失败，When 继续评价，Then 本地进度持续更新，状态提示失败但队列不中断；联网后自动重试。
- `F-018-AC-04` Given 匿名请求或另一用户，When 访问进度表或 RPC，Then RLS 与函数权限拒绝访问当前用户之外的数据。
- `F-018-AC-05` Given 同一账号在两台设备分别开始新卡，When 合并同一 Asia/Shanghai 日期的快照，Then 新卡首次开始 ID 去重并且云端最多保留 50 张。
- `F-018-AC-06` Given 云端已经保留当天 50 张新卡开始记录，When 另一设备上传未开始卡，Then 服务端不接收第 51 张并返回云端记录作为本地额度基准。

### F-019 退出登录与防复活重置

#### 作用与目标

区分“停止同步”和“删除全部进度”，并阻止旧设备重新上传重置前数据。

#### 适用角色、入口与前置条件

读者已通过 GitHub 登录；当前浏览器可能有本地进度，云端可能有一台或多台设备同步的记录。

#### 用户输入契约

| 输入项 | 提供者 | 必填 | 格式与范围 | 示例 |
| --- | --- | --- | --- | --- |
| 退出登录 | 读者 | 否 | 当前设备会话 | 点击退出登录 |
| 全局重置确认 | 读者 | 是 | 必须严格等于 `重置` | 重置 |

#### 可见界面状态与交互

状态 1：全局重置确认

```text
这会清除所有设备上的复习进度。
请输入“重置”继续。
[输入框] [确认] [取消]
```

进入条件：已登录读者点击“重置全部进度”。输入不是 `重置` 或取消时关闭确认且数据不变；输入正确后进入正在重置。

状态 2：正在重置

```text
复习进度
正在重置所有设备的进度…
```

进入条件：确认值严格等于 `重置`。云端成功后全部卡恢复新卡；失败后显示云端失败，本地不清除。

#### 产品状态流

```text
退出登录 → 移除当前登录会话 → 保留本地进度 → 本地模式
点击重置全部进度 → 输入值校验 → 值错误则取消 → 值正确则请求云端重置
云端成功 → 重置版本递增并清除云端 → 清除当前本地 → 其他旧设备下次同步采用空快照
云端失败 → 当前本地与云端保持原状 → 允许稍后重试
```

#### 输出契约

| 输出内容 | 呈现形式 | 触发条件 | 语义要求 | 完整示例 |
| --- | --- | --- | --- | --- |
| 退出结果 | 同步状态栏 | 退出成功 | 保留 localStorage v3，停止云端同步 | 回到本地模式 |
| 全局重置 | 所有设备 | 输入正确且 RPC 成功 | 递增重置版本、删除云端卡片与日期任务，再清空当前本地进度 | 全部卡恢复新卡 |
| 失败保护 | 当前设备 | RPC 失败 | 本地进度不清除 | 提示本地安全保存 |

#### 设计依据

用户确认退出登录保留本地、登录状态重置必须输入 `重置`，并要求使用版本墓碑防止旧设备复活已清除进度。

#### 行为样例

- `SAMPLE-SYNC-005`：退出登录保留本地进度。
- `SAMPLE-SYNC-006`：全局重置后旧设备不能恢复旧快照。

#### 验收标准

- `F-019-AC-01` Given 读者已登录且本地有进度，When 退出登录，Then 本地进度与打卡历史保持不变。
- `F-019-AC-02` Given 读者已登录，When 输入值不是 `重置`，Then 本地和云端都不改变。
- `F-019-AC-03` Given 读者输入 `重置`，When 云端事务成功，Then 重置版本递增，云端记录删除，当前浏览器清空。
- `F-019-AC-04` Given 另一设备仍持有较旧重置版本，When 它再次同步，Then 采用新的云端空快照，旧进度不能上传复活。
- `F-019-AC-05` Given 全局重置 RPC 失败，When 操作结束，Then 当前浏览器的本地进度保持不变。

## 安全与边界

- 浏览器只使用 Supabase publishable key；secret key、service role key 和数据库密码不得进入静态产物。
- 所有公开 schema 表启用 RLS；策略明确限定 `to authenticated` 和 `(select auth.uid()) = user_id`。
- 同步与重置 RPC 使用 `security invoker` 和空 `search_path`，匿名角色无执行权限。
- 新卡首次开始记录单独存储并纳入重置事务；额度由锁定的用户同步状态和服务端计数共同约束，不能只依赖浏览器按钮禁用。
- GitHub 用户资料只用于显示登录状态，不作为数据库授权依据；数据所有权只以 `auth.uid()` 判定。
- 同步资源从插件生成的站点本地路径加载，不使用 CDN。
